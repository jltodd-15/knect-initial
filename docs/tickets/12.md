# 12\. Activity Detail Page

### `Activity Detail Page`

**`1. User Story`**

* `As a User I want to be able to obtain more information on an activity when clicking on it. I also want to be able to plan an event with this activity from viewing the activity.`

**`2. The Architecture & Technical Details`**

* **`The Data Handoff:`** `When a user clicks on an activity card, we want the data from the card to be forwarded to the Activity detail Page. In the future when we add the ability to send activity ideas to either groupchats in the app or without, we will want it to fetch that data.`  
* **`The State Check:`** `If they liked the activity it is likely they will open it. Check if the activity is in their liked_activities array in order to know if the heart icon should be prefilled.`   
* **`Distance Calculation:`** `Using Javascript’s geolib, getDistance function (this function uses the Haversine formula for triangulation), take the user’s location and the activity’s location and convert that output to miles. This will be used/referenced again in Project 13 for the discover tab filters.`  
* **`Make this an event button:`** `The button at the bottom of the page should take them to the create event page, that is found on the planner tab. This should be the exact same as the event page with a couple things prefilled out. First the name of the activity should be the same as the name of the event. Second the location/description should be filled out too. Many activities won’t have locations as they are general ideas.` 

**`3. UI & Layout Requirements`**

* **`The Pictures:`** `This should take up about the top third of the page. If there are multiple images for them to swipe through, indicate this with little grey and white dots at the bottom of the picture, like google maps or instagram.`    
* **`The Body Text:`** `The page in general will be set up like the activity cards, just a whole page not just a card. Under the pictures is the activity name, under that is the location, then the description (fully unlike the cards), then the cost (in a little green <view> box, next to that is the tags. Under that is the button to turn the activity into an event.`  
* **`The Tags:`** `Have the tags be in boxes that look the same as the ones on their profile page. If there are too many of them, have them scroll horizontally.`   
* **`The Action Buttons:`** `The like button should go from the bottom right of the card, to the bottom right of the pictures in the activity details page.`   
  `The “Make This An Event” button should be at the bottom of the page. Knect green with white (depending on dark mode) text.`   
* **`Error states`**`: If there is an error use the same error state message previously used throughout the app.` 

**`4. Acceptance Criteria`**

- [ ] `The data properly passes from the card to the detail page.`  
- [ ] `The heart Icon successfully shows whether they had previously liked the activity or not.`  
- [ ] `The “Make this an Event” button successfully transfers the required data to the create an event page.`  
- [ ] `The distance calculation gives the correct distance, in miles, to location for the user.`  
- [ ] `All data fields show properly.`  
- [ ] `The pictures load properly and can be swiped through if there are multiple.`
