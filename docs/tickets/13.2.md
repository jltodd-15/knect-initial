# 13.2. Tag Affinity Scores Write Logic

### `Tag Affinity Scores`

**`1. User Story`**

* `As a User, I want to have my interests reflected in what content I see on the Discover tab. I want my likes to mean something; they should alter the algorithm to show me more of what I show an interest in.`

**`2. The Technical Architecture`**

* `The tag_affinity_scores are saved in the Users collection under their User ID document, in the private_info subcollection. It should be formatted as a Map/Object, to prevent extra Firestore reads and issues with using the data.`  
  `Users / {User_ID} / Private_info / {Private_ID}`  
* `The scores should add points to all related tags within the activity for each of the following actions:`  
  * `Clicking on an activity = +1 point`  
  * `Liking/Saving an activity = +5 points`  
  * `Creating an event with the activity = +10 points`  
  * `Adding a tag to their profile = +10 points`  
  * `Sending an activity to their friend = +10 points (delay for now)`  
* `//Example state inside Firestore`   
  `tag_affinity_scores: {`   
  `"outdoors": 45,`   
  `"music": 12,`   
  `"bowling": 10,`  
  `“hiking” : 5`  
  `}`  
* `Firestore has a maximum document size. To prevent this from causing an error, limit tag_affinity_scores to 50 tags total. If a 51st tag attempts to be added, remove the lowest scored tag.`   
* `To counteract monotonic and spiraling growth to tag scores, add in a decay of x0.9. This should go into effect when tag_scores_last_dacayed is more than 7 days ago, however, only check this when there is a write; that will keep inactive users from costing database writes and losing their scores over time.`

**`3. UI & Frontend`** 

* `Rapid and repetitive clicks/liking could create unnecessary read/write costs. To prevent this, we need a layer in React Native that creates a 2 second buffer that, if there are no contradictory commands, will then update the tag_affinity_scores.`  
* `If there are contradictory commands, wait another 2 seconds, then update based off of the latest command.`  
* `E.g. If someone likes, then unlikes, then likes an activity, the buffer should wait a couple of seconds before adding the like to the tag affinity scores.`   
* `If a person clicks/views an activity multiple times rapidly (within that 2 second buffer), only count it as one click.`

**`4. Acceptance Criteria`**

- [ ] `When a user Clicks/views an activity, the tags in that activity are updated to add 1 point to each tag`  
- [ ] `When a user Likes an activity, the tags in that activity are updated to add 5 points to each tag`  
- [ ] `When a user creates an activity, the tags in that activity are updated to add 10 points to each tag`  
- [ ] `When a user adds an interest to their profile, give that tag 10 points`  
- [ ] `When there are multiple commands given in rapid succession, the buffer allows only the most recent to affect the scores`  
- [ ] `There are always max 50 tags in the tag_affinity_score`
