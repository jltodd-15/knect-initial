# 0.2. iOS Firebase & Xcode Project Setup

**Status:** Not started. Reviewed 2026-09-03.
**Depends on:** 1.1 (the SDK decision, and the packages it installs)
**Blocks:** `*1.3` (Sign in with Apple), and every later iOS build

---

**Human setup required before this starts.** None of it can be done from the repo:

1. **A Mac with Xcode.** iOS cannot be built on anything else. **Answer this before anything else in the ticket** — without one, nothing here is possible.
2. **Decide the bundle identifier.** See section 2; the current one is a leftover template default.
3. **Add an iOS app to the `knect-db` Firebase project** using that bundle ID, and download `GoogleService-Info.plist`.

**This ticket does not need a paid Apple Developer account.** A free Apple ID is enough to build to the simulator and to run on your own iPhone under a personal team, where the app expires after seven days. The paid membership (~$99/year) is needed for Sign in with Apple, TestFlight and the App Store — all of which belong to `*1.3` and to launch, not here.

**Which is the reason to do this ticket early even if `*1.3` is deferred.** Every ticket after this one is verified on a device, and today the only device this project can build to is Android. Working iOS-only otherwise means iOS breakage accumulates silently for months and arrives all at once. One example already in the tree: `App.tsx` and the other screens ask for `'Anonymous Pro'` and `'Inter'`, **there are no font files in the repo and no asset-link config**, so both platforms are quietly falling back to system fonts — and font linking is per-platform work. That class of problem is cheap to find continuously and expensive to find in a batch.

No features. This is the iOS mirror of 1.1.

**2 - The Architecture & Technical Details**

> **The model, in three lines.** A React Native app has two native halves. `android/` has been configured for Firebase since the prototype; `ios/` never has. Firebase reaches both halves through the same `@react-native-firebase` packages 1.1 installs — what differs is the per-platform config file and the project settings around it.

- **Target Database Collection:** None. This ticket touches no Firestore data.
- **Data model changes:** None.

**What's actually there, verified on the `auth` branch.** The iOS folder has never been touched since the project was generated:

| What | Current state | Why it's a problem |
|---|---|---|
| Bundle identifier | `org.reactjs.native.example.AwesomeProject` — the React Native template default | Not a Knect identifier. Firebase, Apple's App ID, and Sign in with Apple all key off this |
| Project, target, scheme, `PRODUCT_NAME` | `AwesomeProject` everywhere — `ios/AwesomeProject/`, `AwesomeProject.xcodeproj`, `AwesomeProject.xcscheme` | The Xcode project was never renamed |
| `ios/Podfile:17` | `target 'Knect' do` | **Names a target the Xcode project does not have.** `pod install` fails on this alone |
| `ios/Podfile.lock`, `ios/Pods/` | Neither exists | Pods have never been installed. Nothing iOS has ever been built |
| `ios/GoogleService-Info.plist` | Does not exist | The iOS counterpart of `google-services.json`. Without it Firebase cannot initialize |
| `AppDelegate.swift` | No Firebase import, no `FirebaseApp.configure()` | Firebase is never started on iOS |

One thing that is already right, and worth not "fixing": `AppDelegate.swift:27` starts React Native with module name `"Knect"`, which matches `app.json`. **The JS side is correct; the Xcode side is the half that's wrong.** Don't rename the module to match the Xcode project — rename the Xcode project to match everything else.

**The bundle identifier.** Android is `com.knect` (`android/app/google-services.json`, `AndroidManifest.xml`). Matching it on iOS keeps one identifier across both stores and both Firebase apps. **`[DECISION: confirm the iOS bundle ID — `com.knect` to match Android, or something else?]** It has to be decided before the Firebase iOS app is created, because changing it afterwards means regenerating `GoogleService-Info.plist` and re-registering the App ID.

**Renaming the Xcode project is the fiddly part.** It touches the directory name, the `.xcodeproj`, the target, the scheme, `PRODUCT_NAME`, and `PRODUCT_BUNDLE_IDENTIFIER` — and Xcode's own rename does not catch all of them. Verify by grepping the `.pbxproj` for `AwesomeProject` afterwards rather than trusting the rename dialog. **Alternatively, regenerate the iOS folder from the current React Native template with the right name and port the two files that were customized** (`AppDelegate.swift` and `PrivacyInfo.xcprivacy`). For a folder that has never been built, regenerating is often less work and less risky than renaming — **stop and ask before choosing**, because it's a judgment call about a folder nobody has exercised.

**`PrivacyInfo.xcprivacy` needs filling in.** `ios/AwesomeProject/PrivacyInfo.xcprivacy` currently declares `NSPrivacyCollectedDataTypes` as an empty array and `NSPrivacyTracking` as `false`. **1.1 installs Firebase Analytics, which makes both inaccurate**, and an inaccurate manifest is rejected at upload rather than at review. Fill it in here — this is the ticket that owns the iOS manifest.

**What this ticket does not need to know about Apple sign-in.** `*1.3` owns the provider. This ticket only has to leave iOS in a state where a native module can be added and built. The Apple Developer portal work specific to Sign in with Apple — the Services ID, Key ID, Team ID and `.p8` key that Firebase's Apple provider requires — belongs to `*1.3`, not here.

**4 - Security and Scope**

**In scope**

- Rename the Xcode project, target, scheme and `PRODUCT_NAME` to Knect, or regenerate the folder — see section 2.
- Set `PRODUCT_BUNDLE_IDENTIFIER` to the decided bundle ID.
- Fix `ios/Podfile` so its target matches, and run `pod install`.
- Add `GoogleService-Info.plist` to the Xcode project — **added to the target, not just dropped in the folder**, which is the single most common way this silently fails.
- `FirebaseApp.configure()` in `AppDelegate.swift`.
- Fill in `PrivacyInfo.xcprivacy` for Analytics.

**Explicitly out of scope**

- **Sign in with Apple, and the Apple Developer portal work it needs.** `*1.3`.
- **Any auth, any Firestore, any feature.**
- **iOS-specific UI or layout.**
- **TestFlight, provisioning profiles, distribution certificates, App Store Connect.** Real work, later, and none of it blocks a simulator build.
- **Android.** Nothing under `android/` is touched.

**Security rules changes:** No changes needed. This ticket touches no Firestore data.

**Security note:** `GoogleService-Info.plist` is a **client** config, like `google-services.json` — it ships inside the app bundle and is not a secret. It is committed for the same reason the Android one is. ⚠️ **But check `.gitignore` before committing it**: 1.1 fixes the `*firebase*` / `*firestore*` patterns at lines 78–79, and if 1.1 has not landed, a plist with "GoogleService" in the name is fine but anything Firebase-named is not. Verify with `git check-ignore` rather than assuming it committed.

**Files allowlist — touch nothing else.**

```
ios/                        (the whole folder — this ticket owns it)
package.json                only if pod installation requires a change
```

Nothing under `android/`, nothing in `components/`, no `.ts`/`.tsx` file.

**Stop and ask** rather than improvising if: there is no Mac available; the bundle ID has not been decided; the rename-vs-regenerate call needs making; or `pod install` fails for a reason not in the table above.

**5 - Acceptance Criteria**

Verified by one method: **build and run on an iOS simulator from a Mac.**

- `grep -rn "AwesomeProject" ios/` returns nothing.
- `PRODUCT_BUNDLE_IDENTIFIER` is the decided Knect bundle ID, and `org.reactjs.native.example` appears nowhere.
- `ios/Podfile`'s target matches the Xcode target name.
- `pod install` completes and `ios/Podfile.lock` exists.
- `ios/GoogleService-Info.plist` exists, is listed in the Xcode target's resources, and its bundle ID matches `PRODUCT_BUNDLE_IDENTIFIER`.
- `AppDelegate.swift` calls `FirebaseApp.configure()` before React Native starts.
- The app launches on a simulator and all four tabs — Planner, Discover, Circle, Profile — render without a red screen.
- Firebase logs a successful initialization on launch rather than a missing-configuration warning.
- `PrivacyInfo.xcprivacy` declares the data Analytics collects, and `NSPrivacyCollectedDataTypes` is no longer an empty array.
- No file under `android/` was modified.
- `npm run lint` passes.
- `npm test` passes.
