# 4.6. Friends Box & the Friends List Screen (4.4 follow-up)

**Status:** Written 2026-10-10 from Kyson's ruling of 2026-10-09. Not reviewed.
**Depends on:** 4.4 (the friends list, the pending section, the name cache), 4.1 (the root stack)
**Blocks:** nothing. 5 and 7 make the rows and stars on the list screen do something.

> **Why this exists.** 4.4 put the whole friends list under the search bar, so opening the Search tab read one `Users` document per friend. Kyson ruled (2026-10-09): the Search tab shows one Friends box with counts, and the list lives on its own screen. Opening Search must not read every friend, and it is cleaner. Numbered 4.6 although it is built before 4.5 (the token update).

**1 - User Story**
As a User, I want the Search tab to open fast and show me how many friends I have, and to see the full list only when I ask for it.

**2 - The Architecture & Technical Details**
- **Target collections:** `Users/{uid}/Friends` (read), `Users/{friendId}` (read, list screen only).
- **Data model changes:** None.
- **Counts:** two count queries on the signed-in user's own `Friends` subcollection: `status in ["friend", "close_friend"]` and `status == "close_friend"`. They return numbers, not documents, so the cost does not grow with the number of friends. One-time reads, not listeners.
- **A count needs a connection.** If either count fails (offline, or any error), the box shows with no numbers and still opens the list. It is not an error state.
- **The list screen** is 4.4's list, moved: same query, same name cache, same sort, same pages of 10, same pull-down refresh (which clears the name cache). It is pushed on 4.1's root stack. Its count beside the title comes from the rows it has already read, not from a third query.
- **The Search tab** keeps its pull-down refresh and its read-again-on-focus. What reads again is the pending query and the two counts.
- **Keep the logic pure.** The wording of the counts line is a function in `services/friendsList.ts`, tested first. `services/FriendsService.ts` runs the count queries.

**3 - The UI and Layout Requirements**
Design guidance: `docs/design/app-screens/Search` and `FriendsList`. Built on the tokens that exist today; fonts, icons and the new token values arrive with 4.5.

- **Search tab, under the search bar:** the Pending Requests section (unchanged from 4.4), then the Friends box: the word "Friends", the counts line under it, and a chevron on the right. The whole box is one tap target.
- **Counts line:** "12 friends · 2 close friends". Singular at one ("1 friend", "1 close friend"). With no close friends the second half is left off. With no friends it reads "No friends yet".
- **Loading:** a `<SkeletonCard variant="list-row" />` in the box's place.
- **Counts unavailable:** the box with "Friends" and the chevron, no counts line.
- **While a search is showing results,** the pending section and the box are both hidden, as in 4.4.
- **Friends list screen:** a back arrow, the title "Friends", and the number of friends beside it once the list has loaded. Below it, 4.4's list with its skeleton, empty and error states. The empty state's "Find friends" button goes back to the Search tab.
- **Tapping a row does nothing until Project 7. Tapping a star does nothing until Project 5.** The board's line "Tap a star to mark a close friend" is left out until 5.

**4 - Security and Scope**
- **In scope:** the box, the two count queries, the list on its own screen, the root-stack route.
- **Out of scope:** friend requests and starring (5), opening a person (7), the token, font and icon update (4.5), keeping the tab bar visible on the list screen (the board shows it; 4.1 pushes screens on the root stack, above the tabs).
- **Files allowlist:** `components/SearchTab.tsx`, `components/FriendsBox.tsx` (new), `components/FriendsList.tsx`, `components/FriendsListScreen.tsx` (new), `services/FriendsService.ts`, `services/friendsList.ts`, `App.tsx`.
- **Security rules changes:** No changes needed. A count query is allowed wherever the same list query is allowed.

**5 - Acceptance Criteria**
- [ ] Opening the Search tab calls the pending query and the two count queries, and does not call the friends query or read any friend's `Users` document.
- [ ] The box shows the counts line in the wording above, for 0, 1 and many friends.
- [ ] With the counts failing, the box still shows and still opens the list.
- [ ] Tapping the box opens the friends list screen; the back arrow returns to Search.
- [ ] The list screen shows 4.4's list: close friends first, alphabetical, pages of 10, pull down to refresh.
- [ ] `npm test` passes; `npm run lint` reports no errors in the files touched.
