**1 - User Story**
As a User who has been sent a friend request, I want accepting it to make us friends on both sides and give us a chat, all at once or not at all.

**2 - Architecture & Technical Details**

> **The model, in three lines.** A request is two documents: `Users/B/Friends/A` = `"pending"` and `Users/A/Friends/B` = `"request_sent"`, both created by A. Only A can create `"pending"` in B's list (`firestore.rules:112-118`), so that document is the proof A asked. B cannot write A's half (`firestore.rules:129`, and the test at `firestore-tests/friends.test.ts:195`), so acceptance is this Function.

- **Target collections:** `Users/{uid}/Friends` (read, write), `Users/{uid}/Private_info/main` (read), `Chats` (read, create).
- **Data model changes:** None. Every field is in the Master Schema (`MASTER_SCHEMA.md`: `Friends.status`; `Chats.participants`, `participant_hash`, `chat_origin`, `chat_name`).
- **Callable:** `acceptFriendRequest({ requesterId })`. The caller is B; `requesterId` is A. Returns `{ chatId }`.
- **One transaction, in this order:**
  1. Read `Users/B/Friends/A`. If it is `"friend"` or `"close_friend"`, the request was already accepted: change no status, find the chat, return it. If it is anything but `"pending"` (missing, or `"request_sent"`), reject with `failed-precondition`.
  2. **Block check (Decision Log O4).** Read both people's `Private_info/main`. If either has the other in `blocked_users`, reject with `failed-precondition`. The error does not say who blocked whom.
  3. Set `Users/B/Friends/A` to `{ status: "friend" }`.
  4. Set `Users/A/Friends/B` to `{ status: "friend" }`, creating it if it is missing. **Exception:** if A's copy already says `"close_friend"`, leave it. (A can set their own copy to anything; see `firestore.rules:124-128`.)
  5. Find or create the chat (below).
- **Chat find-or-create, written once.** 15.1 specifies one recipe shared by every entry point; this ticket writes it and 15.1 reuses it.
  - `participant_hash` = the participant uids sorted in ascending byte order, joined with a single underscore (15.1). A pure function, tested on its own.
  - Find: `Chats` where `participant_hash ==` the hash **and** `chat_origin == "direct"`, inside the transaction.
  - Create if none: `participants` (the two uids), `participant_hash`, `chat_origin: "direct"`, `chat_name`. `[DECISION: chat_name for a direct chat. 15.1 shows the other person's name as the headline, read live, so nothing useful can be stored. Likely: the empty string.]`
  - **No `recent_message*` fields.** They are the chat-list preview, written only by 15.2's Function.
- **Chat history survives.** If the pair unfriend or block and later re-friend, the same chat is found, with its history (Decision Log, "Blocking removes the friendship").
- **Input checks:** `requesterId` is a non-empty string and is not the caller's own uid; otherwise `invalid-argument`.
- **The caller's uid comes from the auth context only** (5.1's helper).

**4 - Security and Scope**
- **In scope:** the callable, the block check, both status writes, the chat find-or-create and its hash function, their tests.
- **Out of scope:** sending, declining, starring, removing, blocking (all client writes, `*5.3`); the app calling this (`*5.3`); 15.1's other chat entry points, rename and leave; notifications (20); a system message in the new chat; any change to `firestore.rules`.
- **Files allowlist:** `functions/src/acceptFriendRequest.ts`, `functions/src/chats/findOrCreateChat.ts`, `functions/src/chats/participantHash.ts`, `functions/src/index.ts` (the export line), and their tests under `functions/`.
- **Security rules changes:** No changes needed. The Admin SDK bypasses the rules; that does not make a rule gap fixed (Decision Log, "Friend-acceptance rule"). `*3.4` re-checks this Function against the rules.

**5 - Acceptance Criteria** (all by `npm run test:functions`)
- [ ] B accepts A's pending request: both documents read `"friend"`, and one `Chats` document exists with both uids, the right hash, and `chat_origin: "direct"`.
- [ ] The hash for (A, B) equals the hash for (B, A), and uses an underscore between uids in ascending byte order.
- [ ] Accepting twice returns the same `chatId`, creates no second chat, and changes no status.
- [ ] B's copy already `"close_friend"`: nothing is downgraded.
- [ ] No `pending` document from A: rejected, nothing written. Includes the case where only A's `request_sent` half exists.
- [ ] B has blocked A, or A has blocked B: rejected, nothing written, and the error text is the same in both cases.
- [ ] The pair already has a direct chat (from an earlier friendship): it is reused.
- [ ] A group chat with the same two participants (`chat_origin: "group"`) is **not** returned as their direct chat.
- [ ] Not signed in → `unauthenticated`. `requesterId` missing, empty, or the caller's own uid → `invalid-argument`.
- [ ] The created chat has exactly the four fields above and no `recent_message*` field.
