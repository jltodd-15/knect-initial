# 4.2. Theme, Tokens, Shared Components & the Full Sweep

**Status:** Drafted 2026-10-07, all decisions ruled 2026-10-07. Unreviewed as a whole.
**Depends on:** 4.1 (the sweep styles the new navigation, not the old one).
**Blocks:** 4.3, 4.4, and the UI section of every later ticket.

---

**1 - Goals**

- One set of colors, type and spacing for the whole app, defined once in code.
- Dark mode that follows the phone's setting by default, with an override that sticks.
- The three shared states every screen needs: a skeleton loader, an empty state, an error state.
- Every existing screen moved onto all of the above, so the app looks like one app instead of six.

---

**2 - The Architecture & Technical Details**

> **The model, in three lines.** Appendix A is the source for every value: color tokens (A.2), type scale (A.3), spacing (A.4) and radius (A.5), with light and dark variants. They live in `theme/tokens.ts` and are read through one hook, `useTheme()`, from a `ThemeProvider` — no component takes an `isDarkMode` prop anymore (A.6). The shared components live in `components/shared/` and are the only skeleton, empty and error visuals in the app (Appendix B).

- **Target Database Collection:** None.
- **Data model changes:** None.

**The theme**

- `theme/tokens.ts` — every token in Appendix A, typed, with `light` and `dark` values. Plus the `eventColors` list (below).
- `theme/ThemeProvider.tsx` — defaults to the phone's setting (`useColorScheme()`). An override of System, Light or Dark is saved through `utils/storage.ts` and read on launch. Every storage call is awaited (`CLAUDE.md`).
- `theme/useTheme.ts` — the one hook every component calls.
- **Font weights:** 900 for `display` only, 700 below it (A.3).

> **Behavior change worth knowing:** `App.tsx:133` (on `ticket/4.1`) forces light mode on every launch today. After this ticket, someone whose phone is in dark mode opens the app in dark mode.

**The Profile tab's dark-mode switch** (`toggleDarkMode`, `App.tsx:530`) is rewired to set Light or Dark. A three-state System / Light / Dark control is D6's.

**The shared components** (Appendix B, in `components/shared/`)

- `<SkeletonCard variant="activity" | "list-row" />` — grayed placeholder in `surface-alt`. Never a spinner.
- `<EmptyState />` — a message plus an optional action button. Nothing is broken, there's just nothing here.
- `<ErrorState />` — the circle-and-`!` in `danger`, a message prop with the default "Sorry, we couldn't load anything right now.", and an optional retry.

Not in this ticket: `ActivityCard`, `TagChip`, `ProfileHeader` and `FriendActionButton`. Each belongs to the ticket that first needs it (11, 12, 7, 5).

**The sweep**

Every file under `components/` (except `ChatEventWidget.tsx`, below) plus `App.tsx` moves onto the theme: hex values become tokens, `isDarkMode` props and `getStyles(isDarkMode)` go, and the retired iOS grays (`#8e8e93`, `#1c1c1e`, `#2c2c2e`, `#f2f2f7`) go with them. Counted on the ticket stack, 2026-10-07:

| File | Hardcoded colors | `isDarkMode` uses |
| --- | --- | --- |
| `SocialDashboard.tsx` | 150 | 59 |
| `CreateEventModal.tsx` | 81 | 15 |
| `EventPlanner.tsx` | 72 | 18 |
| `ProfilePage.tsx` | 54 | 14 |
| `CreateProfilePage.tsx` | 33 | 7 |
| `DiscoveryFeed.tsx` | 30 | 4 |
| `App.tsx` | 22 | 21 |
| `StatusComposer.tsx` | 21 | 3 |
| Five smaller files | 23 | 15 |

**Most of those colors aren't in Appendix A.** The code uses about 40 distinct values; the common off-palette ones are `#333` (40 uses), `#999` (29), `#666` (25), `#ccc` (22) and `#000` (21). Mapping each one to the nearest token is a judgment call that changes what a screen looks like. So **before the first file is swept, Claude Code writes the full mapping — every distinct hex in the app → its token, and every one-off font size, spacing and radius value → its scale value — and stops for approval.** It never invents a token.

Colors outside Appendix A, ruled:

- **Event colors are their own palette, not theme tokens.** `CreateEventModal.tsx:23` lets a user pick one of six colors for an event (`#10b981`, `#3b82f6`, `#8b5cf6`, `#ec4899`, `#f97316`, `#eab308`), and that value is stored on the event. They move into `theme/tokens.ts` as an `eventColors` list, unchanged and the same in light and dark. Blue stays as one of them.
- **The Close Friends star uses `primary`.** The amber `#fbbf24` in `ProfilePage.tsx` goes.
- **The stray reds and greens** (`#dc2626`, `#fca5a5`, `#fef2f2`, `#ff8080`, `#4ade80`) **fold into `danger`, `danger-surface` and `primary`.** The exact mapping goes in the approval list.

**The sweep applies all of Appendix A:** colors, dark mode, and font sizes, spacing and radius onto the A.3–A.5 scales. The one-off sizes (9, 11, 13, 15, 17, 18, 22) go, so layouts will shift slightly — expected, not regressions.

**The four spinners.** Line numbers on `ticket/4.1`.

- `App.tsx:315` (launch, while checking whether you're signed in) and `App.tsx:443` (after sign-in, while checking your profile exists) become **the Knect logo** — the "Kn" mark from the sign-in screen, centered. Static for now; an animated version may come later and is out of scope here.
- `DiscoveryFeed.tsx:118` (Discover loading) becomes `<SkeletonCard variant="activity" />` cards.
- `CreateProfilePage.tsx:295`, the spinner inside the signup submit button, **stays.** It's a "working on it" signal on a button, not content loading, and 2.3's test checks it.

**`components/ChatEventWidget.tsx` is left out of the sweep.** Nothing imports it, so nothing on screen uses it. It stays untouched, and the grep checks below skip it.

**Tests.** Removing the `isDarkMode` prop changes how existing tests render components. Updating those calls is expected; any assertion that changes is said out loud per `CLAUDE.md`'s testing protocol.

**3 - The UI and Layout Requirements**

- No redesign. Layout, copy and behavior stay; only where the colors, sizes and spacing come from changes.
- Small visual shifts are expected wherever an off-palette value moves to its token or scale value. Those are the point, not regressions.
- Every screen has to work in both light and dark.

**4 - Security and Scope**

**Files this ticket may modify**

- `theme/tokens.ts`, `theme/ThemeProvider.tsx`, `theme/useTheme.ts` — **new.**
- `components/shared/SkeletonCard.tsx`, `EmptyState.tsx`, `ErrorState.tsx` — **new.**
- Every file under `components/` except `ChatEventWidget.tsx` — styling and the `isDarkMode` prop only.
- `App.tsx` — wrapping in `ThemeProvider`, removing `isDarkMode` / `toggleDarkMode` state, the two launch spinners, and styling.
- `__tests__/` — new tests for the theme and the shared components; existing tests only where the `isDarkMode` prop removal requires it.
- `DEVICE_TESTS.md` — a 4.2 section. `CLAUDE.md` (its Styling section), `README.md` — lines this ticket makes stale.

**In scope**

- The theme files, the provider and the hook.
- The three shared components.
- The sweep of every existing screen except `ChatEventWidget.tsx`.
- The three spinner replacements above.

**Explicitly out of scope**

- Any change to logic, data, copy or layout.
- `ActivityCard`, `TagChip`, `ProfileHeader`, `FriendActionButton`.
- An animated launch logo.
- The three-state System / Light / Dark control (D6).
- `ChatEventWidget.tsx`.
- Wiring any screen to Firestore. Screens on sample data stay on sample data.

**Security rules changes: No changes needed.** This ticket reads and writes no data.

**Stop and ask** if: a color or size has no target in the approved mapping; a sweep seems to need a logic change; or a test assertion (not just a render call) has to change.

**5 - Acceptance Criteria**

Verified by `npm test` and `grep` for the code, and **one device** for how it looks.

**Tests are written before the implementation.** The theme and the shared components have no device dependency, so their tests run first, fail, and drive the code.

- Every token has both a light and a dark value — a test, not a read-through.
- With no override saved, the theme follows the phone's setting.
- An override is saved, and is still in effect after the app restarts.
- `<SkeletonCard />` renders both variants; `<EmptyState />` renders with and without its action; `<ErrorState />` shows the default copy when given no message and calls retry when tapped.
- `grep -rn "isDarkMode" --include=*.tsx --include=*.ts --exclude=ChatEventWidget.tsx --exclude-dir=node_modules .` returns no results.
- `grep -rnE "#[0-9a-fA-F]{3,8}\b" --exclude=ChatEventWidget.tsx components App.tsx` returns no results. Colors live only under `theme/`.
- `grep -rn "#8e8e93\|#1c1c1e\|#2c2c2e\|#f2f2f7" --include=*.tsx --exclude=ChatEventWidget.tsx --exclude-dir=node_modules .` returns no results.
- `grep -n "ActivityIndicator" App.tsx components/DiscoveryFeed.tsx` returns no results; `CreateProfilePage.tsx`'s button spinner is still there.
- On the device: with the phone in dark mode, the app opens dark; in light mode, light.
- On the device: launch shows the "Kn" logo, not a spinner; Discover loading shows skeleton cards.
- On the device: every tab, the chat thread, the create-event modal and the onboarding screens look right in both modes — a checklist in `DEVICE_TESTS.md`, one line per screen per mode.
- `npm test` passes. `npm run lint` reports no errors in the touched files.
