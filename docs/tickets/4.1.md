# 4.1. React Navigation Migration

**Status:** Built 2026-10-07 on the `ticket/4.1` branch; not yet verified on a device.
**Depends on:** 0.1 (the app has to boot), 1.1 (`react-native-firebase` is installed; same native-install pattern).
**Blocks:** 4.2, 4.3, 4.4, Project 7.

> **Human setup, before verifying:** after Claude Code installs the packages, run `cd ios && pod install` on the Mac and do a fresh build. The new libraries have native parts, so a JS reload is not enough.

---

**1 - Goals**

- Replace the hand-rolled tab switch with React Navigation, so later tickets have real routes to navigate to.
- Five tabs: Planner, Discover, Search, Circle, Profile.
- Everything that works today still works the same way after this lands. This is a plumbing ticket, not a redesign.

---

**2 - The Architecture & Technical Details**

> **The model, in three lines.** Before this ticket, navigation was one state variable, `activeTab` (`App.tsx:69`), and four `{activeTab === AppTab.X && <Screen/>}` lines (`App.tsx:447–468`); `components/Navigation.tsx` drew the bar. After it, a `NavigationContainer` holds a root stack whose only screen is a five-tab bottom-tab navigator, so Project 7 can push a profile screen on top. The loading, sign-in and onboarding screens stay outside the navigator, exactly as they render today.

- **Target Database Collection:** None.
- **Data model changes:** None.
- **Packages:** `@react-navigation/native`, `@react-navigation/bottom-tabs`, `@react-navigation/native-stack`, `react-native-screens`. `react-native-safe-area-context` is already installed (`package.json`, ^5.5.2) — don't add it again.

**The five tabs, in order**

1. **Planner** — calendar icon, as today.
2. **Discover** — **compass icon, new.** Drawn with `react-native-svg`, which is already a dependency. No icon library.
3. **Search** — the magnifying glass, moved from Discover (`Navigation.tsx:26–32`). Renders a placeholder screen with only the "Search" banner. 4.3 fills it.
4. **Circle** — as today.
5. **Profile** — as today.

**The tab bar keeps today's look.** The existing custom bar in `components/Navigation.tsx` is handed to the navigator as its tab bar.

**Behavior that has to survive the move**

- **The tab bar hides while a chat is open.** `SocialDashboard` calls `onChatOpen` / `onChatClose` (`App.tsx:462–463`) and `App.tsx:470` hid the bar. Same behavior after.
- **Sending an activity to the Planner.** `handlePlanActivity` (`App.tsx:277–282`) stores the item and participants, then switches to Planner, where `EventPlanner` reads `initialProposal` / `initialParticipants`. Discover and Circle must still be able to do this. How it's carried (route params or the existing state) is the implementer's call.
- **After signup, the user lands on Planner** (`App.tsx:250`), even if the last user signed out from a different tab.
- **Signing out** returns to the sign-in screen.

**Remove what it replaces.** The `activeTab` state and the four conditional lines go. `AppTab` in `types.ts` goes too if nothing else imports it after the move.

**Tests.** The navigation libraries need Jest mocks, which go in `jest.setup.js`. The existing `App.*` tests must still pass. `jest.setup.js` already records that mounting the tab tree in a test hangs in this environment, so tests prove the wiring, not the rendered tabs.

*(Line numbers above are against `ticket/3.3`, the base this ticket was cut from.)*

**3 - The UI and Layout Requirements**

- Visually the same as today, except Discover's compass, Search's magnifying glass, and the new Search placeholder.
- No loading, empty or error states. This ticket reads no data.
- Tab bar hidden while a chat is open; visible again on close.

**4 - Security and Scope**

**Files this ticket may modify**

- `package.json`, `package-lock.json`, `ios/Podfile.lock` — the four packages above.
- `App.tsx` — the signed-in render block, the `activeTab` state and `handlePlanActivity`. The auth screens above it are untouched.
- `components/Navigation.tsx` — becomes the navigator's tab bar.
- `components/SearchTab.tsx` — **new**, banner only.
- `types.ts` — removing `AppTab` only.
- `jest.setup.js` — navigation mocks only.
- `android/app/src/main/java/com/knect/MainActivity.kt` — only if `react-native-screens`' install steps require it.
- `DEVICE_TESTS.md` — a 4.1 section. `CLAUDE.md`, `README.md` — only lines this ticket makes stale.

Nothing else. In particular no screen component (`EventPlanner`, `DiscoveryFeed`, `SocialDashboard`, `ProfilePage`) changes, and no color changes anywhere — that's 4.2.

**In scope**

- The four packages, the container, the root stack, the five-tab navigator.
- The compass icon; the magnifying glass on Search.
- Keeping the four behaviors above working.

**Explicitly out of scope**

- Deep-link configuration (Project 21) and notification routing (Project 20).
- The public profile screen. Project 7 registers it on the root stack.
- The Search tab's contents (4.3) and the friends list (4.4).
- Any styling, theming or dark-mode change (4.2).
- Moving the auth screens into the navigator.

**Security rules changes: No changes needed.** This ticket reads and writes no data.

**Stop and ask** if: a package needs `react-native-gesture-handler` or `react-native-reanimated` (neither is installed, and both are bigger native installs than this ticket plans for); a Gradle file needs editing; or keeping a behavior above seems to need a change inside a screen component.

**5 - Acceptance Criteria**

Verified by **one device** (an iPhone release build, or Android), plus `npm test`.

- `npm test` passes, including every existing `App.*` test.
- The tab bar shows five tabs in order: Planner, Discover, Search, Circle, Profile.
- Discover shows a compass; Search shows the magnifying glass.
- Each of Planner, Discover, Circle and Profile renders what it rendered before this ticket.
- Search shows the "Search" banner and nothing else.
- Opening a chat in Circle hides the tab bar; closing it brings the bar back.
- "Plan this" from Discover lands on Planner with the activity filled in. Same from a chat in Circle.
- A fresh signup lands on Planner.
- Signing out returns to the sign-in screen; signing back in shows the tabs.
- `grep -n "activeTab ===" App.tsx` returns no results.
- No file under `components/` changed except `Navigation.tsx` and the new `SearchTab.tsx`.
- `npm run lint` reports no errors in the touched files.
