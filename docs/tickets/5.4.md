# 5.4. Friend Buttons — Accept, Decline, Star & the Shared Action Button

**Status:** Written in the Project 5 edit pass, 2026-10-10. No open decisions. Not reviewed.
**Depends on:** `*5.3` (the actions), 4.4 and 4.6 (the pending section, the friends list screen), 4.5 (tokens and icons), `*5.2` deployed (for Accept on a device)
**Blocks:** 7 (mounts the shared button on a profile)

**1 - User Story**
As a User, I want to accept or decline a request where I see it, star a friend where I see them, and have one button that always tells me where I stand with a person.

**2 - Architecture & Technical Details**

> **The model, in three lines.** The pending section and the friends list were built display-only (`components/PendingRequests.tsx:80`, `components/FriendsList.tsx:49`). This ticket makes them act, through `*5.3`'s functions only. No screen talks to Firestore or to a Function directly.

- **Data model changes:** None.
- **`<FriendActionButton />`** (Appendix B.1), built here in `components/shared/` because 5 is the first ticket that needs it. It takes a person's uid, reads `getRelationship`, and shows one of five states. **Copy and styles are Appendix B.1's, exactly:**

| State | Copy | Style |
|---|---|---|
| Not friends | "Send a Friend Request" | `primary` fill, `onPrimary` text |
| Request sent | "Sent" | `textDisabled` fill, `textSecondary` text. Disabled |
| Request received | "Accept Request" + "Decline" | Two buttons: `primary`, and `danger` with `onDanger` text |
| Already friends | "Unfriend" | `danger` fill, `onDanger` text |
| Blocked by me | "Unblock" | `surfaceAlt` fill, `textPrimary` text |

- **Optimistic, with revert (Appendix B.1).** A tap shows the new state at once. If the write fails, the button goes back and a short message says it did not work.
- **The button is built and tested here but mounted nowhere.** Its home is a person's profile, which is ticket 7. Until 7 lands, nothing in the app can send a request or unfriend; those are checked on a device together with 7. Accept, Decline and the star are reachable now, with requests added by hand in the Console as for 4.4.
- **Pending Requests rows** gain "Accept Request" and "Decline". Accepted or declined, the row leaves the section and the badge count drops. Accept then re-reads the Friends box's counts.
- **Friends list rows:** the star becomes a button. Tapping it flips `friend` ↔ `close_friend`. **The row stays where it is** until the list is next loaded or pulled down, so it never moves under the finger. The line "Tap a star to mark a close friend" from the `FriendsList` board is added under the title.
- **After Accept the user stays on the Search tab.** No chat opens: the Circle tab runs on sample data until Project 15, so there is no real chat screen to open.
- **A request that is refused because the other person has blocked you** fails like any other failed write, with the same message: **"Couldn't send the request. Try again."** It must not hint at a block. Every other failed action says "That didn't work. Try again."

**3 - UI & Layout**
Design guidance: `docs/design/app-screens/Search`, `FriendsList` and `Profile`. Tokens and icons from `useTheme()` only.
- **Loading:** the button shows a `list-row`-height skeleton block while the relationship is read. A button that is saving stays in its new state; no spinner.
- **Error reading the relationship:** the button is not shown. The row still shows the person.
- **Failure of an action:** revert, plus the message above.
- **Tap targets:** every button and the star are at least `sizes.touchMin` (44).
- **Tapping a row still does nothing** until ticket 7.

**4 - Security and Scope**
- **In scope:** the shared button and its tests; Accept and Decline on pending rows; the star toggle.
- **Out of scope:** mounting the shared button anywhere (7 does it), including on Search result rows; the profile screen and its "..." menu (7); any Block control (the profile menu is 7's, the in-chat one is 15.2's), so **nothing in the app can block after this ticket**; a list of people you have blocked, which has no ticket; cancelling a sent request; notifications; restyling the Search tab or the friends list beyond what is named here.
- **Files allowlist:** `components/shared/FriendActionButton.tsx` (new), `components/PendingRequests.tsx`, `components/FriendsList.tsx`, `components/FriendsListScreen.tsx` (the hint line only), and their tests. **Not** `components/SearchTab.tsx`.
- **Security rules changes:** No changes needed.

**5 - Acceptance Criteria** (by `npm test`; the device checks go in `DEVICE_TESTS.md`)
- [ ] The button shows the right copy for each of the five states.
- [ ] Each tap calls exactly one `*5.3` action with the right uid.
- [ ] A failed action reverts the button and shows the message.
- [ ] Accepting removes the row, lowers the badge, and re-reads the counts. Declining removes the row and lowers the badge.
- [ ] Tapping a star flips it and calls the star action once; a failure flips it back.
- [ ] No component in this ticket imports from `@react-native-firebase/*`.
- [ ] `grep -rn "FriendActionButton" components App.tsx` finds it only in its own file.
- [ ] Device checks are written in `DEVICE_TESTS.md`: accept (both lists and the chat document in the Console), decline, and star, using Console-seeded requests. Send and unfriend are listed there as waiting on ticket 7.
