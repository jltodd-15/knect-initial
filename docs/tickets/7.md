# 7\. Public Profile Routing

## `Public Profile Routing`

**`1. User Story`**

* `As a user I want to be able to easily see any person’s profile that I am interacting with. This allows me to gain feedback from the app and build a community easily.`

**`2. The Architecture & Technical Details`**

* **`The Navigation Payload:`** `Whenever a user is seeing the profile picture, or username, of another user, they should be able to tap on it and be navigated to that User’s profile picture. This should be done primarily by using the Unique User ID.`  
* **`Target Database:`** `Collection: Users, Document: Users ID`   
* **`The Relationship Check:`** `The app should check the private_info document in the Users collection to check the blocked_users array to see if either user has the other as a blocked user. If they do, all action should be denied (even though hopefully they couldn’t even see their profile pic or username in the first place).` 

**`3. UI & Layout Requirements`**

* **`The Triggers:`** `All the places you can tap on someone’s profile picture or username. Groupchats (in the chat and the groupchat overview), in any activity with someone, search tab when searching for them, when viewing the list of friends/close friends.`  
* **`The Loading State:`** `When loading the profile page, you can just show a blank white or gray screen (depending on if in dark mode). I don’t think it should take too long so no loading animation should be needed.`   
* **`The View State (Data Display):`** `It should look exactly like your own profile page, however, we want to remove some key elements. There shouldn’t be any log out button, dark mode toggle, or calendar sync button. There shouldn’t be any way for them to change their interests, name, bio, or profile picture.`  
  `All features still there: Profile Picture, Username, Bio, and interests, all in the same style as the profile tab already in place.`   
  `There is one button that should be added: The friend status button. It should show the ability to send a friend request, accept one, if one is sent, or block/unfriend. More details for this button are outlined in project 4 under 3.2 User Profiles.`   
* **`The Error State:`** `If a user’s profile has been deleted but is somehow still accessible, or if internet is lost while trying to load the profile page, then, the screen should show an error message stating “This profile is inaccessible right now” in red (the same red as the block button), with a red error symbol (exclamation mark with circle around it).`   
* **`The Blocked State:`** `If user A has blocked user B, we should first prioritize screening their visibility from user A’s app. If however, they are still visible then they should be able to view their profile with an “unblock” option for the friend status button. User B should only receive the error message when trying to see user A’s profile.`    
* **`The Mid-Updated State:`** `If a profile is updated while someone is viewing the profile, the screen must be reloaded before those updates are viewed.`

**`4. Acceptance Criteria`**

- [ ] `When a user clicks on another user’s trigger, the app successfully fetches their User ID and can load their profile information.`   
- [ ] `The app doesn’t overload with data or have any errors while trying to load User info.`  
- [ ] `The friend status button properly shows the most up to date info for that person’s relationship to the User.`  
- [ ] `All information on the profile is the most up to date and updated, as of the time it was clicked.`  
- [ ] `Blocked profiles are visible to the blocker, but the opposite is not true for the blocked user.`
