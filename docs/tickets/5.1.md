**1 - Goals**
The repo has a `functions/` project that builds, runs in the local emulator, and can be tested with one command, so the first real Function (`*5.2`) is only about its own logic.

**2 - Architecture & Technical Details**

> **The model, in three lines.** Some writes must not come from a phone: anything a client could lie about, or anything that needs to read data the client cannot read. Those run as Cloud Functions with the Admin SDK, which bypasses `firestore.rules`. A callable Function is called by name from the app and receives the caller's verified uid.

- **Data model changes:** None.
- **Layout:** a `functions/` folder at the repo root with its own `package.json`, `tsconfig.json`, and `src/index.ts`. TypeScript. It is a separate npm project: the app's `node_modules` and the Functions' are not shared.
- **`firebase.json`** gains a `functions` block pointing at `functions/`, and a `functions` entry under `emulators`.
- **Runtime:** `[DECISION: Node version for Functions. Likely 22, the newest the platform supports and within the repo's ">=20" engines line (package.json:58-60).]`
- **Generation and region:** 2nd-generation Functions. `[RESEARCH: which region the Firestore database is in (Console → Firestore → the location shown beside the database name). DECISION: deploy Functions to that region, or leave the default us-central1. Likely: match the database.]`
- **The callable auth pattern, written once.** A small helper that every callable uses first: no signed-in caller → reject with `unauthenticated`. The caller's uid comes only from the verified auth context, never from the request body.
- **What proves the harness.** `[DECISION: the harness needs one callable to test against. Likely: create acceptFriendRequest here as a shell that does only the auth check and input check, then rejects with "unimplemented". *5.2 fills it in. Nothing throwaway is written.]`
- **Tests:** `npm run test:functions` from the repo root starts the Firestore emulator, runs the Functions' own Jest suite against it, and stops. It never touches the real project. `npm test` never runs it, and it never runs `npm test`.
- **Deploy:** an `npm run functions:deploy` script, the Functions equivalent of `npm run rules:deploy`. **Not run in this ticket.**

**4 - Security and Scope**
- **In scope:** the `functions/` project, the emulator entry, the auth helper, the test command, the deploy script, the shell callable if the decision above goes that way.
- **Out of scope:** any real Function logic (`*5.2`); the app calling a Function (`*5.3`); scheduled Functions and triggers (16.x, 17.x, 15.x add what they need); deploying; the Auth emulator; CI.

- **New dependencies:** inside `functions/` only: `firebase-functions`, `firebase-admin`, `typescript`, `jest`, `ts-jest`, `firebase-functions-test`. None in the app.
- **Security rules changes:** No changes needed.
