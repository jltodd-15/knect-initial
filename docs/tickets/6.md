# 6\. Profile Picture Uploads

## `Profile Picture Uploads & Storage`

**`1. User Story -`** `As a User, I want to be able to put unique pictures as a profile picture so that friends can identify me, and I can identify my friends easily.`

**`2. The Architecture & Technical Details`**

* **`Target Storage:`** `Users collection, Friends (subcollection)`  
* **`Target Database:`** `User ID doc → profile_picture_url, Friend’s User ID doc → friend_profile_picture_url`  
* **`Data Formatting & Compression:`**   
  * `Max file size of 2MB`  
  * `We should then have it compressed down to 100Kb-300Kb before it goes to Firebase`  
  * `Enforce a square 1:1 aspect ratio`  
  * `Convert to a JPEG or WebP (read that that was good for mobile apps)`  
  * `We will need permission requests for IOS (Info.plist) and Android (Android Manifest.xml) to access the user’s photo gallery`  
  * `The app should use Cache-Control Headers to store the profile pic locally, and Cache-Busters for when they change that profile pic`  
  * `react-native-fast-image: Instead of using the <Image> component, use <FastImage> for the profile pictures. This allows us to cache more of them in the User’s phone, that way it renders faster and we don’t incur higher costs. Only use this for profile pictures and activity images.`   
    * `Use the priority prop (e.g., high for the main profile view, normal for the discover feed or the chat view)so the app knows which images to load first.`  
    * `Note: This will require downloading react-native-fast-images. That looks like running these two commands into the terminal:`   
      `npm install react-native-fast-image,`  
      `and cd ios && pod install for IOS.`  
* **`The Upload Flow:`**  
  * `Step 1: User adds a profile pic when setting up the account (probably easiest to make this mandatory rn)`  
  * `Step 2: App compresses the picture`  
  * `Step 3: The device should have that profile picture cached`  
  * `Step 4: Take the picture and save it in Firebase Cloud Storage, then take the URL it makes for the database`  
  * `Step 5: Firebase should be updated to include their profile pic url`  
  * `Step 6: If they update it, then the cache should be busted and the data in firebase overwritten`  
  * `Step 7: Any of their friend’s profile pictures should become stored in that user’s subcollection Friends (not actually sure now if we need that, I’m thinking we should store that on the device for speed purposes, let me know if you think the schema would be better for that)`

**`3. UI & Layout Requirements`**

* **`The Trigger:`** `User signs up, and clicks on “Add Profile Picture” button; User clicks on their profile picture in settings → it opens the same add profile picture page on the sign up`  
* **`The Loading State:`** `After adding and cropping the picture, there should be a loading animation (semicircle that moves around)`  
* **`The Success State:`** `It should show their profile pic and a statement, “Your profile pic has been added(updated)!”, after a second, automatically navigate them to the next page in the sign up process or their profile page if they are updating`  
* **`The Error State:`** `If they lose internet during this stage there should be a symbol of wifi with an X over it and a statement, “Internet Connection Lost”`

**`4. Acceptance Criteria`**

- [ ] `When they click the “Add Profile Picture” button, it navigates them to their device’s camera roll.`  
- [ ] `When they choose and crop a picture, the app successfully compresses it.`  
- [ ] `The file is properly saved in the User ID doc as profile_picture_url`  
- [ ] `The database and their cache should update every time they update their profile picture.`  
- [ ] `Their picture is updateable.`  
- [ ] `The UI should move smoothly and update when the profile pic is uploaded.`
