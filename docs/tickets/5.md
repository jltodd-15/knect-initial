# 5\. Friend Request Logic

## `Friend Request Logic & Close Friend’s`

**`1. User Story:`** `As a user, I need to be able to send, accept, decline, block, and remove friends to build my network. Once someone is my friend, I want to be able to "star" them as a Close Friend so I can separate my inner circle from my broader network.`

**`2. The Architecture (Developer Note on Security)`**

* **`Two-Way Street:`** `Friendships are mutual. When a request is accepted, a Batched Write must occur to ensure both users reflect the new friendship.`  
* **`One-Way Street (Close Friends):`** `Starring a user as a "Close Friend" is a private organizational action. It only requires a single database write to the user's own device; the other person does not need to know they were starred.`  
* **`The Security Rule Constraint:`** `To prevent trolls from forcing friendships, our Firebase Rules state that User A can only create a request in User B's database if the document ID exactly matches User A's UID.`  
* **`Solution:`** `The developer MUST use a Firestore "Batched Write" for every single action below to ensure both users' databases update at the exact same millisecond. If a user loses internet halfway through, the Batch cancels the whole operation.`

**`3. Technical Implementation Details (The State Machine)`**

* **`Action A: Sending a Request`** `(Batched Write)`  
  * *`Trigger:`* `User A taps "Add Friend" on User B's profile.`  
  * *`Write 1:`* `Create doc in User B's Friends subcollection (Doc ID = User A's ID). status = "pending".`  
  * *`Write 2:`* `Create doc in User A's Friends subcollection (Doc ID = User B's ID). status = "request_sent".`  
* **`Action B: Accepting a Request`** `(Batched Write)`  
  * *`Trigger:`* `User B taps "Accept" in their pending list.`  
  * *`Write 1:`* `Update User B's doc to status = "friend".`  
  * *`Write 2:`* `Update User A's doc to status = "friend".`  
* **`Action C: Declining a Request`** `(Batched Delete)`  
  * *`Trigger:`* `User B taps "Decline" in their pending list.`  
  * *`Action:`* `Delete the "pending" document from User B's subcollection AND delete the "request_sent" document from User A's subcollection. (Silently, no notification).`  
* **`Action D: Toggling "Close Friend" Status`** `(Single Write)`  
  * *`Trigger:`* `User taps the "Star" icon next to a current friend's name in the Search Tab widget.`  
  * *`Action:`* `If starred, update the user's specific friend document to status = "close_friend". If they un-star it, revert status back to "friend".`  
* **`Action E: Removing a Friend`** `(Batched Delete)`  
  * *`Trigger:`* `User taps "Remove Friend".`  
  * *`Action:`* `Delete the friend document from BOTH users' subcollections simultaneously, regardless of whether they were a "friend" or "close_friend".`  
    * **`Action F: Blocking a User`** `(Batched Write)`  
  * *`Trigger:`* `User A taps "Block" on User B's profile (usually hidden under a "..." menu) or inside a chat.`  
  * *`Write 1 (The Block):`* `Update User A's Private_info document. Add User B's UID to the blocked_users array (using Firestore's arrayUnion method).`  
  * *`Write 2 (Cleanup):`* `Delete User B's document from User A's Friends subcollection (if it exists).`  
  * *`Write 3 (Cleanup):`* `Delete User A's document from User B's Friends subcollection (if it exists).`  
  * *`Action:`* `(Silently, no notification is sent to User B).`

**`4. Required Denormalized Data Payload`** `Whenever a document is created in the Friends subcollection, the frontend MUST pass:`

* `status (String: "pending", "request_sent", "friend", "close_friend")`  
* `friend_name (String)`  
* `friend_profile_picture_url (String)`

**`5. UI & Layout Requirements`**

* **`Profile Button States:`** `The "Action" button on a user's profile dynamically displays:`  
  * `"Add Friend" (if no document exists)`  
  * `"Requested" (Disabled grey state, if status == "request_sent")`  
  * `"Accept / Decline" (if status == "pending")`  
  * `"Friends" (if status == "friend" OR "close_friend")`  
* **`The Star Widget (Search Tab):`** `The list of friends must read the status field. If status == "close_friend", render a filled-in star. If status == "friend", render an empty outline star.`

**`6. Acceptance Criteria`**

- [ ] `Sending a request successfully creates documents in BOTH databases simultaneously.`  
- [ ] `Accepting a request successfully updates BOTH statuses to "friend".`  
- [ ] `Tapping the Star icon successfully updates only the acting user's database to "close_friend".`  
- [ ] `A user cannot send a friend request to someone who is in that person’s blocked_users array.`
